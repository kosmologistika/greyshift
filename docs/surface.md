# The mod surface

Every type a module may name and what it may do with it, generated with the SDK from the marks on the engine's types. `observe` on a component is its `Add<..>` and `Remove<..>` lifecycle.

| Type | Grants | What |
| --- | --- | --- |
| `Add<shared::flight::components::InFlight>` | observe | The entity a `shared::flight::components::InFlight` was just added to |
| `Add<shared::shop::ShopOffer>` | observe | The entity a `shared::shop::ShopOffer` was just added to |
| `Remove<shared::flight::components::InFlight>` | observe | The entity a `shared::flight::components::InFlight` was just taken off, the value still on it |
| `Remove<shared::shop::ShopOffer>` | observe | The entity a `shared::shop::ShopOffer` was just taken off, the value still on it |
| `bevy_ecs::hierarchy::ChildOf` | read, insert | The entity this one is a child of. Despawning the parent despawns it |
| `bevy_replicon::shared::replication::Replicated` | insert | Marks an entity for replication to clients |
| `server::player::Participant` | read | This connection is playing the current round. The `lobby` writes it at the round-start edge and for late joins; gamemode rules read it and nothing else, so no rule re-derives participation from ready-up state that was already resolved before any rule existed. |
| `server::player::session::PlayerRecord` | read | Server-private player record. Never replicated; usernames stay off the wire until something client-side consumes them. |
| `shared::appearance::Appearance` | read, insert | What an entity is supposed to look like: a base sprite, a draw depth, and the layers over it. Carried across the wire so the client and the editor compose sprites the same way; the server itself never renders. |
| `shared::appearance::BurnOut` | read, insert | [`FadeIn`]'s exit twin, with fire: the entity is burning away and will be despawned when `until` passes. The server owns the clock and the despawn; the client renders whatever burning means (a pixel dissolve). Consumers insert this instead of despawning outright, so nothing pops |
| `shared::damage::DamageDealt` | observe | A hit landed: what `entity` takes after every modifier. Announced before the ledgers change, so a consequence sees the world the blow arrived in - the killing blow still bleeds, leaks and screams |
| `shared::death::Dead` | read | Marker for a deceased body. Sits on the corpse alongside its accumulated `Damageable`. Future revive systems (defib, clone) remove it; future medical systems (autopsy, organ harvest, undertaker NPCs) query for it. |
| `shared::death::Killed` | observe | A controlled body just died, with the kill resolved against the freshness of its `LastHitBy` stamp. `killer` is `None` for unattributed deaths - environment, self, or a stale stamp - which score nobody. Server-triggered; gamemodes observe it for scoring and bounties |
| `shared::facing::Facing` | insert | Server-authoritative facing of any entity that can be oriented. Default South matches SS14 convention so freshly spawned mobs face the camera in a top-down layout. Replicated immutable so observers fire on every change - render-side reacts by re-indexing the atlas row without resetting animation playback. |
| `shared::flight::components::FlightRules` | read | What ends a flight and what it passes through. Seeded whole by [`launch`] and [`launch_ray`], so a launcher authors the rule set in one place and a landed entity carries none of it into whatever launches it next |
| `shared::flight::components::InFlight` | read, observe | An entity in flight, launched by `launcher`. Replicated descriptor the client renders from directly: `origin_world + dir * speed * elapsed` is the smooth line at the true angle, never tile-snapped. `launcher` is the entity that started the flight (thrower, blast source, gun shooter); used for excluding the launcher from self-hits and attributing damage. |
| `shared::follow::Following` | read, insert | On a follower (a ghost): the entity it orbits. [`track_target`] keeps the follower's `TilePos` equal to the target's; the client derives the orbit visual from this. Removed when the follower moves, or when the target despawns. |
| `shared::gamemode::hud::HudBanner` | insert | A headline with an optional subtitle and countdown. Rules spawn these as replicated entities and one generic client plugin renders whatever exists, so a new gamemode needs no client code |
| `shared::gamemode::hud::HudScoreboard` | read, insert, mutate | A live table of participants. Same contract as [`HudBanner`] |
| `shared::gamemode::rule::RuleStarted` | observe | Fired on a rule entity once it is spawned and live. Rule plugins observe this and filter by querying their own marker component, so no generics are needed |
| `shared::gamemode::scope::EndScope` | trigger | Request to end a scope. Rules never touch `NextState<RoundState>` - they trigger this and the driver decides what it means |
| `shared::gamemode::scope::ScopeEnded` | read | Set once a teardown is accepted, so a second [`EndScope`] from a racing rule is a no-op |
| `shared::gamemode::scope::ScopeEnding` | observe | The rescue window, fired once per accepted teardown and before the cascade. Anything that must outlive the scope has to leave its hierarchy here |
| `shared::ghost::Ghost` | read | Marker for the ghost behavior surface: orbit, ghost-only chat, the "return to body" verb, future ghost-specific UI. Independent from the PVS markers below so non-ghost incorporeal entities can reuse the visibility layer without inheriting ghost behaviors. |
| `shared::hands::Hands` | read | Mob's hand state. For MVP, only tracks which hand is active - held-item slots land when the inventory system arrives. |
| `shared::map::Map` | read | Marker for a map entity. The map is the parent of every `Tile` entity belonging to it (via `ChildOf`), so despawning the map cascades to its tiles. Other domain components (atmos defaults, ambient music, parallax background) attach here as separate components. |
| `shared::map::TilePos` | read, insert | Position of an entity on a map's tile grid. Carries the owning map's entity ref so multiple maps (lavaland, centcom, the station) can coexist without coordinate collisions. |
| `shared::mob::Mob` | read | Marks an entity as a mob - the in-world body that can move, be pushed, occupy tiles, etc. |
| `shared::movement::components::Movable` | read, insert | Marker: this entity participates in tile-locked movement. Carries `MoveSpeedModifier` + `MoveCooldown` via require so both are always present wherever this marker is. `Facing` is also required - every movable entity has an orientation, and the movement applier writes it on each successful step. |
| `shared::player::ControlledBy` | read | Marks a controllable entity (a mob, ghost, etc.) as controlled by a particular player identified by their stable [`PlayerId`]. |
| `shared::player::SessionPlayer` | read | The [`PlayerId`] a live connection authenticated as. Server-side only, lives on the connection entity next to `AuthorizedClient`; never replicated. |
| `shared::role::Role` | insert | A `RolePrototype` id. Lives on the connection entity as the assignment record, which is what makes a team survive a match change, and is copied onto each body so gameplay can read it without walking back to the session. |
| `shared::shop::ClearEarned` | trigger | Zeroes `earned` on every wallet. The wallet's owner stays its only writer: a rule that wants a fresh tiebreak asks, it does not reach in |
| `shared::shop::Purchased` | observe | Money moved, the offer still standing; what handing over `product` means is the observer's call (a body owed it, an item in hand, a skill granted) |
| `shared::shop::ShopDone` | observe | The shopper is finished with the offer, which comes down right after this fires; a mode closing a shelf itself goes through the same `close_offer` |
| `shared::shop::ShopOffer` | read, insert, mutate, observe | What this connection may buy right now, on the connection entity. Absent means no shop at all: whoever raised the offer decides when someone may spend, and the shop never asks why. Server-side; [`ShopUpdate`] is its wire mirror |
| `shared::shop::Wallet` | read, mutate | A player's money, on their `PlayerRecord` entity so it survives a reconnect. `balance` is what they can spend; `earned` accumulates every credit and never goes down, for round-level tiebreaks. One component: both move on the same credit and reset through the same owner |
| `shared::storage::Gripping` | read | On a hand slot: what the hand holds on to without storing it, see ADR 0010 |
| `shared::storage::HandSlot` | read | Marks a [`Container`] as one of a mob's hands - which side, and whose. The mob's [`Hands::active`] selects which hand pickup/drop act on; `owner` is the replicated slot-to-holder link, so both sides resolve "whose hand is this" without relying on `ChildOf` (which is derived, not replicated). A container without `HandSlot` (a toolbox) is openable storage, not a hand. |
| `shared::storage::Stored` | read, insert | In-container location source: this entity sits inside `container`, not on a tile. The container is any entity with a [`Container`] - a hand or a toolbox. Mutually exclusive with [`TilePos`] - the strip observers guarantee an entity never carries both. The relationship derive forces it immutable, so every re-store is a fresh insert that re-fires the invariant |
| `shared::trigger::Triggered` | observe | Fires on the item as it goes off, in a hand, on the floor or mid-flight |
